# Режим ROCKET: настройка прошивки и рулей

Инструкция по сборке, прошивке и настройке режима ROCKET для ArduPlane.
Ориентирована на корпус 60 x 730 мм, 1.3-1.5 кг, четыре руля на хвосте,
полётный контроллер Matek H743 Slim v4, двигатель класса RD1-300.

Ветка: `rkt` в https://github.com/VladimirAndreev1985/ardupilot

---

## 1. Что это такое

ROCKET - это отдельный режим полёта ArduPlane (номер **27**), который ведёт
ракету от пускового устройства до перехода в обычный самолётный режим.
Он добавляет:

- конечный автомат фаз: `PAD -> RAIL -> BOOST -> COAST -> TRANSITION`,
  плюс `ABORT` как аварийная ветка;
- стабилизацию относительно направления пуска, а не относительно горизонта;
- микшер на четыре руля, работающий для любой геометрии от «+» до «X»;
- интегратор скорости по акселерометру, чтобы режим работал без GPS и без
  датчика воздушной скорости.

Важно понимать границу: режим **не** управляет траекторией и **не**
выводит ракету на заданную точку. Он держит ракету по оси пуска, пока она
быстрая, а затем передаёт управление штатному режиму (по умолчанию FBWA).

### Фазы

| Фаза | Когда | Что делает |
|---|---|---|
| `PAD` | режим включён, ракета на столе | рули в нейтрали, ждёт старта |
| `RAIL` | ускорение выше `RKT_ACCEL_THR` в течение `RKT_ACCEL_TIME` | рули в нейтрали на `RKT_RAIL_TIME` |
| `BOOST` | сход с направляющей | активная стабилизация, пока работает двигатель |
| `COAST` | ускорение упало (выгорание) | стабилизация со своими коэффициентами |
| `TRANSITION` | скорость ниже `RKT_TRANS_SPD` или истёк `RKT_CST_TIME_MAX` | переход в `RKT_TRANS_MODE` |
| `ABORT` | отклонение больше `RKT_ABORT_LIM` | рули в нейтрали, можно вытолкнуть парашют |

Рули остаются нейтральными в `PAD` и `RAIL` намеренно: на направляющей
они всё равно ничего не могут, а скоростной напор уже большой, поэтому
любое отклонение - это только нагрузка на приводы и на крепление.

## 2. Сборка прошивки

### Окружение

Нужны ARM-компилятор и Python-окружение с `empy`:

```bash
export PATH=/opt/gcc-arm-none-eabi-10-2020-q4-major/bin:$PATH
source ~/venv-ardupilot/bin/activate
```

Без первой строки сборка под железо не найдёт компилятор. Без второй
`waf` упадёт на отсутствии `empy`.

### Прошивка под Matek H743

```bash
cd ~/ardupilot-rocket
git checkout rkt
./waf configure --board MatekH743
./waf plane
```

Результат: `build/MatekH743/bin/arduplane.apj`. Текущий размер - 1 566 304 Б
при 137 624 Б свободно, то есть запас по флешу есть.

Заливка через Mission Planner (Initial Setup -> Install Firmware ->
Load custom firmware) или:

```bash
./waf plane --upload
```

### Проверка, что режим в прошивке есть

После заливки в Full Parameter List должны появиться параметры `RKT_*`.
Если их нет - залита не та прошивка.

## 3. Обязательные параметры

Готовый файл: `ArduPlane/rocket_params_example.parm`. Его можно загрузить
целиком через Mission Planner (Full Parameter List -> Load from file), но
разделы с батареей, CRSF и OSD нужно поправить под свою обвязку.

### Режим на переключателе

```
FLTMODE1 27        # ROCKET
FLTMODE6 5         # FBWA для посадки
```

### Пределы углов

Обязательно. Штатные самолётные пределы не дадут ракете смотреть вверх:

```
PTCH_LIM_MAX_DEG 90
PTCH_LIM_MIN_DEG -90
ROLL_LIMIT_DEG 90
```

### Детекция старта

```
RKT_ACCEL_THR 15    # м/с^2, порог ускорения
RKT_ACCEL_TIME 50   # мс, сколько держать порог
RKT_RAIL_TIME 100   # мс, рули нейтральны после детекции
```

`RKT_RAIL_TIME` считается по длине направляющей: на 1 м при среднем
ускорении около 240 м/с² сход занимает примерно 90 мс.

### Фазы и переход

```
RKT_BST_TIME_MAX 3.0   # с, чуть больше времени работы двигателя (2 с)
RKT_CST_TIME_MAX 15    # с, максимум на COAST
RKT_TRANS_SPD 30       # м/с, ниже этого - переход
RKT_TRANS_MODE 5       # 5=FBWA, 11=RTL, 12=LOITER, 10=AUTO
RKT_ABORT_LIM 60       # град, отклонение для аварии
```

### Коэффициенты стабилизации

```
RKT_P_KP 0.8    RKT_P_KD 0.3    # тангаж
RKT_Y_KP 0.5    RKT_Y_KD 0.2    # курс
RKT_R_KP 0.01   RKT_R_KD 0.05   # крен
```

**Крен требует коэффициентов примерно в 100 раз меньше, чем тангаж.**
Это не опечатка. Момент инерции по крену у тонкого корпуса - около
8e-4 кг·м², а все четыре руля дают крен одновременно, поэтому
эффективность по этой оси огромная. В SITL значение 1.0 (которое стояло
по умолчанию) раскручивало ракету до 180° на 2000 °/с и уводило в ABORT;
0.05 тоже расходилось. Держит только 0.01.

### Интегратор скорости

```
RKT_DRAG_K 0.00067
```

Считается как `0.5 * rho * Cd * A / m`. Для корпуса 60 мм
(A = 0.00283 м²), Cd примерно 0.5 и массы 1.3 кг получается 0.00067.
Это единственный источник скорости, когда нет GPS и датчика воздушной
скорости, поэтому ошибка здесь напрямую искажает масштабирование рулей.

### Масштабирование рулей по скорости

```
RKT_SPD_SCL_REF 30    # м/с, при этой скорости коэффициенты номинальные
RKT_SPD_SCL_MIN 0.2   # на 240 м/с
RKT_SPD_SCL_MAX 2.0   # на малой скорости
```

Коэффициент равен `RKT_SPD_SCL_REF / скорость` с ограничением
`MIN..MAX`. На 180 м/с это даёт 0.2, то есть отклонение рулей
уменьшается в пять раз - иначе на пике напора ракета ломается об
собственные рули.

## 4. Настройка рулей: «+» и «X»

### Нумерация и функции

Четыре руля - это четыре отдельные servo-функции. Номера выходов можно
выбрать любые, функции фиксированы:

| `SERVOn_FUNCTION` | Имя в коде | Положение при `RKT_FIN_ANGLE 0` | При `45` |
|---|---|---|---|
| 190 | `k_rocket_fin1` | верх | верх-право |
| 191 | `k_rocket_fin2` | право | низ-право |
| 192 | `k_rocket_fin3` | низ | низ-лево |
| 193 | `k_rocket_fin4` | лево | верх-лево |

Положение считается **от направления «вверх», по часовой стрелке, если
смотреть на ракету с хвоста** (вслед полёту). Руль n стоит под углом
`phi_n = RKT_FIN_ANGLE + 90*(n-1)`.

Пример для выходов 1-4:

```
SERVO1_FUNCTION 190
SERVO2_FUNCTION 191
SERVO3_FUNCTION 192
SERVO4_FUNCTION 193
```

### Геометрия

```
RKT_FIN_ANGLE 0     # конфигурация «+» (крест)
RKT_FIN_ANGLE 45    # конфигурация «X»
```

Допустимы и промежуточные значения 0-45, микшер считает геометрию
тригонометрически. Pre-arm проверка отклоняет значения вне 0-45.

Вид с хвоста:

```
   RKT_FIN_ANGLE 0              RKT_FIN_ANGLE 45

        fin1                   fin4         fin1
         |                        \         /
  fin4 --+-- fin2                   --+--
         |                        /         \
        fin3                   fin3         fin2
```

### Формула микшера

Отклонение руля создаёт силу по касательной к корпусу, поэтому крен от
всех рулей одинаков, а вклад в тангаж и курс зависит от положения руля:

```
fin_n = aileron + elevator*sin(phi_n) - rudder*cos(phi_n)
```

При `RKT_FIN_ANGLE 0` это сводится к обычному кресту - вертикальная пара
работает курсом, горизонтальная тангажом:

```
fin1 = aileron - rudder       (верх)
fin2 = aileron + elevator     (право)
fin3 = aileron + rudder       (низ)
fin4 = aileron - elevator     (лево)
```

При `RKT_FIN_ANGLE 45` каждый руль несёт обе оси с коэффициентом 0.707:

```
fin1 = aileron + 0.707*( elevator - rudder)
fin2 = aileron + 0.707*( elevator + rudder)
fin3 = aileron + 0.707*(-elevator + rudder)
fin4 = aileron + 0.707*(-elevator - rudder)
```

### Что реально даёт «X»

Распространённое утверждение, что «X» даёт больше управляющего момента,
неверно. Сумма `sin²(phi_n)` по четырём рулям равна 2 при любом угле
установки, поэтому полный момент по тангажу и курсу у «+» и «X»
одинаков. SITL это подтверждает: максимальное отклонение 14.0° для «+»
против 14.2° для «X» на одинаковой траектории.

Настоящая разница в другом:

- **Насыщение.** В «X» каждый руль обслуживает обе оси, поэтому при
  одновременном запросе по тангажу и курсу руль упирается в упор раньше.
  В «+» у каждой оси своя пара рулей, и оси не конкурируют.
- **Компоновка.** «X» часто выбирают из-за направляющей: рули не
  попадают на пусковой рельс, а стабилизатор удобнее крепить.

То есть «X» выбирают по механике, а не по аэродинамике.

### Проверка знаков на столе

**SITL это не проверяет** - симулятор моделирует силы по той же
геометрии, что и микшер, поэтому согласованную ошибку знака оба примут.
Проверять надо руками.

Порядок:

1. Поставьте `RKT_FIN_ANGLE 0` временно, даже если у вас «X». В кресте
   каждая ось отвечает за свою пару рулей, и ошибку видно сразу.
2. Включите режим MANUAL и подайте ручку.
3. Сверьте по таблице:

| Команда | Ожидаемая реакция |
|---|---|
| ручка на себя (elevator +) | fin2 (право) отклоняется, fin4 (лево) в противоположную сторону |
| ручка вправо (aileron +) | все четыре руля отклоняются в одну сторону по окружности |
| педаль вправо (rudder +) | fin3 (низ) отклоняется, fin1 (верх) в противоположную сторону |

4. Каждый руль, который идёт не туда, разворачивается своим
   `SERVOn_REVERSED 1`. Не правьте это сменой функций и не меняйте знаки
   в коде.
5. Верните `RKT_FIN_ANGLE 45`, если у вас «X», и ещё раз проверьте: по
   каждой оси должны отклоняться все четыре руля.

Проверка крена - самая важная. Ошибка знака по крену означает
положительную обратную связь, а при коэффициентах крена, которые тут
нужны, ракета уйдёт в раскрутку за доли секунды.

### Пределы приводов

```
SERVO1_MIN 1000
SERVO1_MAX 2000
SERVO1_TRIM 1500
```

Диапазон функции руля - +-4500 (то есть +-45°) в единицах
`SRV_Channel`, он задан в `SRV_Channel_aux.cpp`. Механические упоры
ограничивайте через `MIN`/`MAX`, а не через коэффициенты.

Шарнирный момент при 180 м/с на руле 50 x 40 мм - отдельный вопрос; его
надо посчитать под конкретную хорду, размах и положение оси, иначе
привод класса ES08 может не додержать.

## 5. Проверка в SITL

В прошивке есть модель ракеты (`libraries/SITL/SIM_Rocket.cpp`): кривая
тяги RD1-300 (291.8 Н·с, пик 330 Н, 2 с), направляющая, силы на рулях,
демпфирование, расход топлива.

### Запуск одного случая

```bash
cd ~/ardupilot-rocket
source ~/venv-ardupilot/bin/activate
./waf configure --board sitl && ./waf plane
python3 -u Tools/autotest/rocket_sitl_test.py --frame rocket --duration 18
```

### Варианты фрейма

| Фрейм | Что проверяет |
|---|---|
| `rocket` | номинальный пуск, 5° от вертикали, конфигурация «+» |
| `rocket-vertical` | строго вертикально |
| `rocket-tilted` | 30° от вертикали; летит по дуге до апогея и переходит в следующий режим (наклонная траектория — не отказ) |
| `rocket-nofins` | нулевая эффективность рулей |
| `rocket-x45` | конфигурация «X», рули на 45/135/225/315° |

Для `rocket-x45` геометрия задаётся **дважды**: фреймом для симулятора и
параметром `RKT_FIN_ANGLE 45` для прошивки. Модель SITL не умеет читать
параметры машины, поэтому файл `models/rocket-x45.parm` выставляет
параметр сам.

### Все случаи сразу

```bash
bash Tools/autotest/rocket_cases.sh
```

Текущий результат:

| Случай | Фазы | Крен | Отклонение | Итог |
|---|---|---|---|---|
| 1. номинал | → TRANS | 2.2° | 14.0° | PASS |
| 2. без GPS | → ABORT | 180°* | 89.6° | PASS (ABORT ожидаем) |
| 3. наклон 30° | → ABORT | 13.0° | 89.9° | PASS (ABORT ожидаем) |
| 4. без рулей | → TRANS | 0.5° | 20.4° | PASS |
| 5. X-45 | → TRANS | 3.4° | 14.2° | PASS |

\* 180° в случае 2 - это разворот эйлеровых углов при проходе через
вертикаль, а не раскрутка. Угловая скорость там 8 °/с. Настоящее
расхождение выглядело как 2000 °/с.

Апогей около 1090 м, пик 180 м/с, 24 g истинного ускорения.

### Ручной запуск

```bash
Tools/autotest/sim_vehicle.py -v ArduPlane -f rocket --console --map
```

Дальше в MAVProxy:

```
mode ROCKET
arm throttle
servo 9 2000
```

Зажигание - выход 9, потому что режим держит канал throttle в нуле.

### Важно про eeprom.bin

SITL сохраняет параметры в `eeprom.bin` и подхватывает их при следующем
запуске. Один прогон без GPS оставляет `EK3_SRC1_*` в нулях и портит все
последующие. `rocket_sitl_test.py` удаляет файл перед каждым запуском;
если запускаете вручную - удаляйте сами.

Ещё: новый файл модели `.parm` читается через `os.listdir` на этапе
**configure**, поэтому после добавления нужен `./waf configure`, а не
просто пересборка.

## 6. Полёт без GPS

Корпус рассчитан на работу без GPS, и здесь есть два подводных камня.

### Арминг

```
ARMING_SKIPCHK 24
```

Не 8. Бит 3 (значение 8) снимает проверку захвата GPS, но остаётся бит 4
(значение 16) - группа INS. В ней `AP_Arming_Plane::ins_checks` вызывает
`AP::ahrs().pre_arm_check`, и для почти вертикального корпуса это даёт
отказ «EKF3 Roll/Pitch inconsistent 85 deg»: резервный DCM не может
разрешить тангаж около 85°. Нужны оба бита, то есть 24.

### Порядок включения

GPS должен быть подключён до того, как EKF получит начало координат.
Если стартовать сразу без GPS, EKF никогда не инициализируется и арминг
не произойдёт вообще. Правильная последовательность: дождаться
готовности EKF с GPS, включить ROCKET, и только потом отключать GPS.

### Известное ограничение

**Полёт без GPS сейчас всегда заканчивается в ABORT.** Это не артефакт
симулятора, а пробел в логике.

Интегратор скорости считает по ускорению вдоль оси корпуса. Пока ракета
летит прямо, это работает: на входе в COAST оценка 156.6 м/с против
истинных 180.4 м/с, то есть 13% занижения. Но когда ракета начинает
заваливаться на баллистической дуге, ускорение по оси корпуса перестаёт
соответствовать скорости по траектории, и оценка завышается. Условие
перехода COAST → TRANSITION по `RKT_TRANS_SPD` не срабатывает, ракета
продолжает заваливаться, и первым срабатывает порог `RKT_ABORT_LIM` 60°.

Варианты решения (пока не реализованы):

1. Добавить в условие перехода скорость спуска по барометру или время от
   выгорания, а не только скорость.
2. Поднять `RKT_ABORT_LIM` выше естественного угла заваливания.

Второй вариант проще, но он снижает защиту от настоящей потери
управления. С GPS этого ограничения нет: случаи 1, 4 и 5 переходят в
TRANSITION штатно.

## 7. Что проверить до первого пуска

- [ ] В Full Parameter List видны параметры `RKT_*`
- [ ] `FLTMODE` на нужном положении переключателя = 27
- [ ] `PTCH_LIM_MAX_DEG 90`, `PTCH_LIM_MIN_DEG -90`, `ROLL_LIMIT_DEG 90`
- [ ] `RKT_FIN_ANGLE` соответствует фактической геометрии рулей
- [ ] Знаки всех четырёх рулей проверены на столе (раздел 4)
- [ ] `RKT_R_KP` 0.01, не 1.0
- [ ] `RKT_DRAG_K` пересчитан под фактическую массу и диаметр
- [ ] `RKT_RAIL_TIME` соответствует длине направляющей
- [ ] Шарнирный момент посчитан, привод держит на 180 м/с
- [ ] Если без GPS: `ARMING_SKIPCHK 24`, и понимание, что будет ABORT
- [ ] Логирование включено: `LOG_BITMASK 1582775`, `LOG_DISARMED 1`
- [ ] Парашют, если есть, проверен отдельно от режима

### Про акселерометр

Истинное ускорение на пике - 24 g, а ICM42688P измеряет +-16 g. Выше
этого показания обрезаются, и EKF получает заниженное ускорение. Поэтому
в `LOG_BITMASK` включены Raw IMU и Fullrate Attitude: по логу надо
посмотреть, где именно началось обрезание. Это ограничение датчика, его
нельзя настроить параметрами.
